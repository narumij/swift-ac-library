# Swift版の共通事項

アルゴリズムを選ぶ前に、Swift固有の使い方・算術の前提・グラフ状態の意味を確認します。

## 導入とimport

この文書は同じリポジトリの開発中ソースに対応し、現在のmanifestはSwift 6.2以降を要求します。
AtCoder 2025搭載の凍結版そのものの説明ではありません。
`compatible/AtCoder/2025`は競技環境互換の保守版、
`release/AtCoder/2025`は搭載版の凍結状態、`main`は開発版です。

ここで説明する開発版APIには、Package.swiftの依存に次を指定します。

```swift
.package(url: "https://github.com/narumij/swift-ac-library", branch: "main")
```

対象ターゲットのdependenciesに
`.product(name: "AtCoder", package: "swift-ac-library")` を追加し、
ソースで `import AtCoder` と書きます。C++のヘッダーincludeは不要です。
ジャッジの搭載APIは古い場合があるので、その環境の版を確認してください。

## 添字・区間・型

添字は0始まりのIntです。区間は半開区間[l,r)、つまりlを含みrを含みません。
許可されたAPIでは空区間も使えます。個数は非負です。本家の上限10^8は入力制約であり、
そのサイズのメモリ確保が実機で成功するという保証ではありません。

例は64bit環境のIntを使います。C++のintはInt32、long longはInt64に対応し、
Swift Intに置き換えたからといってアルゴリズムの数値範囲まで広がりません。
添字・容量・積・中間計算は型と文書の制約に収めてください。
制約外入力の挙動は保証しません。Debugのassertは入力検証APIではなく、
Releaseでは消える場合があるため、特定の停止方法に依存しないでください。

各API欄は引数を用意した状態の呼出例、末尾の使用例は具体的な入力を含むコードです。
ジェネリック型は可能な場合に推論されます。フローの辺型は
`MFGraph<Int>.Edge`、`MCFGraph<Int, Int>.Edge` と書きます。
フィールドはfrom・to・cap・flow、最小費用流ではさらにcostです。

## 所有権と変更

DSU・FenwickTree・SegTree・LazySegTree・MFGraph・MCFGraph・SCCGraph・TwoSATは非コピー型です。
変更する操作にはvarを使います。値渡しは所有権の移動であって、暗黙に独立した複製を作りません。

DSU・FenwickTree・SegTree・LazySegTreeはO(n)の独立複製を作るclone()を公開しています。
他のグラフ型には現時点で公開cloneはありません。
borrowing引数は消費せず読み、inout引数は変更を許可します。
LazySegTreeの読取りは遅延更新を伝播するためmutatingです。
引数なしの構築は空の構造を作りますが、各APIの添字制約は引き続き守る必要があります。

## 代数と有限の数値型

SegTreeの演算は結合律と左右の単位元を必要としますが、可換でなくても構いません。
LazySegTreeはさらに恒等写像・合成で閉じた写像集合を必要とし、
mapping(f,op(x,y)) = op(mapping(f,x),mapping(f,y))を満たします。
composition(f,g)はgの後にfを適用します。

数学上の集合が無限でも、実装は有限の型です。途中で生じるすべての連続区間の集約値が
表現可能な範囲にある必要があります。遅延更新では、ある要素に適用された更新列の
任意の連続部分の合成も表現可能である必要があります。
最終結果がInt内でも中間値が収まるとは限りません。
無限大の番兵は更新しても意味を保つ必要があり、Int.min/Int.maxへ無条件に足すと桁あふれします。

計算量は演算・比較・コールバックが定数時間という前提です。
大きい独自の値などではそのコストを掛け、Unicode比較では文字自体の大きさも考慮してください。

## 最大流の内部状態

辺ごとに容量cと流量f（0 ≤ f ≤ c）を保持します。
残余グラフにはf<cなら順方向、f>0なら逆方向の辺があります。
flow(s,t)は現在の状態から増加させ、s,t以外の頂点の正味流入を保ちます。
戻り値はtへの正味流入の増加分です。
flow_limitはその呼出しの増加分を制限し、累積流量の上限ではありません。

min_cut(s)は現在の残余グラフでsから到達可能な頂点を返します。
実行可能な初期フローから最大流を最後まで求めた後なら最小s–tカットになりますが、
任意の流量制限付き呼出しの後に常に最小とは限りません。
change_edgeは1辺しか変えず、他の頂点のフロー保存則は修復しません。
編集後の実行可能性は呼出側で保ちます。
最大流と異なり、最小費用流のflow/slopeは同じグラフで繰り返し呼ばないでください。

## 並行利用とサニタイザーの範囲

動的な法や畳み込みキャッシュには共有状態があり、サニタイザー成功は任意の並行利用の証明ではありません。
現在のサニタイザーCIは子プロセスのexit系を除外します。
TSanではコンパイラ不具合のためDSU2種と最小費用流も除外し、通常・ASanでは残しています。
測定反復は10回へ復帰済みです。これらは検証範囲の制限であり、アルゴリズムの新たな保証ではありません。

## 版による修正

開発版では、ModIntの狭い整数型からの構築と、floor_sumの負係数・整数境界の計算を修正しています。
古い搭載版には残っている場合があります。ModInt・Mathの各章を読み、利用版と合わせてください。
